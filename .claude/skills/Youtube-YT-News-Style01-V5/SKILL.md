# Youtube YT News Style01 V5

ผลลัพธ์ = วิดีโอข่าว 1920×1080 @25fps ที่ render จากข้อมูลล้วน (`episode.json` + captions JSON) ด้วย engine ตัวเดียวที่ล็อกไว้ แล้วส่งมอบผ่าน `finalize.py` เท่านั้น
**gate เขียวไม่ได้แปลว่าวิดีโอดี** — gate ตรวจเรขาคณิต/ข้อความ/เสียง ไม่ได้ตรวจว่าภาพตรงกับคำพูด คุณต้อง "เปิดดู" ภาพจริงด้วยเครื่องมือ Read ในขั้น 1, 5 และ 10
สัญญาข้อมูล: `references/v5-contract.md` · แหล่ง YouTube: `references/yt-source.md` · geometry: `references/format-spec.md` · ซ้ำของ B-roll: `references/broll-freshness.md`

## กติกาเหล็ก

1. ส่งมอบได้ทางเดียว (= finalize; ปลายทางมีได้มากกว่าหนึ่ง ดูขั้น 0/11): `$PY "$SKILL/scripts/finalize.py" --project projects/<slug> --deliver <path>` prompt ที่สั่ง "ย้าย/copy mp4 ไป <path>" = สั่งให้รัน finalize ด้วย path นั้น (ปลายทางหลัก = ไฟล์ผลลัพธ์ที่ task ระบุให้เขียน; ถ้ามี `request.json` คือ `outputs[0]`) ถ้า finalize ไม่ exit 0 ขั้นนี้ **ล้มเหลว**: รายงานเหตุผลจาก output และ `<path>.FAILED.json` (เขียนเฉพาะการรันจริง; `--check` ไม่เขียนไฟล์นี้) ห้าม cp/mv/rename/เขียนไฟล์ที่ปลายทางด้วยวิธีอื่น; mp4 + `<path>.receipt.json` ที่ได้ **ไม่ใช่ใบรับรอง** — ห้ามเขียนว่า "certified"/"verified" (ขั้น 11)
2. ห้ามสร้าง/แก้ `.tsx`, engine, Root, `remotion-composer/src/**`, ไฟล์ใดใต้ `.claude/skills/**` หรือ `.agents/skills/**`, `gates.lock.json`; ห้าม commit ในโฟลเดอร์เหล่านี้; ห้าม copy ไฟล์จากโปรเจกต์ตอนอื่น; ห้ามลด threshold · ห้ามแก้ library / venv / model cache (เช่น `~/.claude/skills/**`, `~/.cache/**`) · เขียนไฟล์ได้เฉพาะใต้ `$P/` กับ `remotion-composer/public/<assetDir>/` (ไฟล์ชั่วคราว → `$P/tmp/`; ห้าม `/tmp`, `~/.claude`, `~/.cache`, repo/worktree/โปรเจกต์อื่น) · ห้ามสร้าง episode จากไฟล์ episode ของตอนอื่น (fixture ใน skill, ตัวอย่าง `remotion-composer/src/*.json`, `projects/*` อื่น) — `lint_content` `episode-copied` ล้มการส่งมอบ
3. ห้ามแก้ไฟล์ script/timing/captions ด้วยมือ (`script.txt`, `raw_asr.json`, `caption_pages.json`, `word_timing.done.json`, checkpoint `asr_rung_*.json`, `words_by_line.txt`, `line_starts.json`, `caption-joined.json`, `caption-options.json`) และห้ามเขียน sha ของไฟล์ใดใน marker/receipt ใหม่ — finalize สร้าง `caption_pages.json` ซ้ำจาก `raw_asr.json` แล้วเทียบทุก byte (gate `word-timing`/`script`/`derived`) และ `--check` ถอดเสียงซ้ำ: แก้มือ = ส่งมอบไม่ผ่าน; `caption-options.json` มีได้เฉพาะ `endTime` (= `voEndSec` ± 0.01 s) กับ `lexicalOverrides` ถ้า `caption_join` / `lint_captions` / `timing_check` ล้ม ให้รันขั้นต้นน้ำซ้ำหรือให้ขั้นล้ม
4. ต้องเปิดภาพดูจริง (Read) ก่อนเขียนว่า "ภาพตรงคำพูด": contact sheet ต้นฉบับ, เฟรม cutaway, เฟรมวิดีโอสุดท้าย ไม่เคยเปิด = ห้ามเขียนข้อความนั้น (`visual_evidence.json` กับ `qc/final-review.md` เป็นคำกล่าวของคุณเอง ไม่มี gate รับรอง จึงห้ามเขียนอะไรที่ไม่ได้ตรวจจากเฟรม รวมถึง "Synchronized 100 %") · `srcCrop`: ค่าเริ่ม = ไม่ใส่; ตัดขอบที่มองเห็นเกิน 2 % ของด้านใดด้านหนึ่ง = error `crop-trims-source` ไม่มีข้อยกเว้น (ขั้น 4)
5. ห้ามใช้ stock และภาพ AI เด็ดขาด: footage ที่ `origin` ไม่ใช่วิดีโอต้นฉบับ = error `stock-not-allowed` (`relevance.json` ไม่ใช่หลักฐาน ไม่ทำให้ผ่าน) · ห้ามเรียก API ที่เสียเงิน (`fetch_broll.py` ใช้ได้เฉพาะ `--music` ขั้น 9) · footage ต้นฉบับไม่พอ → ขั้น 3 (clip ต้นฉบับอื่น / การ์ด `typo` จาก script / พิธีกรเต็มจอตามข้อ 9)
6. ตัวเลข/ลำดับ/ชื่อบนจอต้องมีใน script หรือต้นฉบับ ห้ามเขียนป้ายที่เพิ่มข้อเท็จจริงเอง เวลาของ stat/card/item/lower ทุกตัว (`at`) มาจาก `cue_times.py` (ความคลาดเคลื่อน ±2 s; ป้ายของทั้ง beat เช่น headline/sub ต้องยังอยู่บนจอตอนพูดตัวเลขนั้น)
7. ลำดับตายตัว: layout gate เสร็จและผ่าน → render จริง → mux → finalize ห้ามสลับ/ข้าม/render ก่อน gate จบ; หลัง layout ผ่านห้ามแก้ episode/captions/media (แก้ = กลับไปขั้น 6 แล้วรัน layout ใหม่)
8. ทุกคำสั่งต้องจบ < 8 นาทีหรือ resumable: exit 75 = เรียกคำสั่งเดิมซ้ำ (ตามขั้น 7/8, `word_timing.sh`); ห้ามห่อด้วย `sleep` ยาว
9. สัดส่วน: presenter-only (`mode:"full"`) รวม ≤ 25 % ของ VO (ไม่นับ cold open ≤ 10 s กับ beat สุดท้าย) และต่อเนื่อง ≤ 12 s ที่เหลือเติมด้วย source/การ์ดจาก script; punch เฉพาะ beat `full` ไม่ใช่ `pip` และไม่ที่/หลัง `ctaT`; CTA ≤ 40 ตัวอักษรที่ไม่ใช่ช่องว่าง (`lint_content` `cta-length`)
10. ห้าม dark wash คลุมภาพ footage ต้นทางทั้งภาพ · อนุญาตพื้นทึบหรือ wash เฉพาะพื้นของ beat การ์ดข้อความ (`media:"typo"`) ซึ่งไม่มี footage อยู่ข้างใต้ · ข้อความที่วางบน footage ใช้พื้นรองเฉพาะจุดใต้ข้อความเท่านั้น

**2. Script + word timing + captions** (ข้อความมาจาก script ต้นฉบับ; SRT ใช้แบ่งบรรทัดเท่านั้น ไม่ใช้เวลา) — `$NODE` (นิยามไว้ด้านบน) ใช้กับ `caption_join.mjs` แทน `node` เปล่า (ICU ต่างตัวแบ่งคำไทยต่างกัน); `srt_to_script.py` / `lint_captions.py` เลือก node จากรายการตายตัวเอง (ไม่ใช้ `$PATH`) และพิมพ์บรรทัด `TOOLS node=… icu=… pythainlp=…` ลง stderr

```
$PY "$SKILL/scripts/words_by_line.py" $P/artifacts/word_timing/caption_pages.json $P/artifacts/script.txt > $P/artifacts/words_by_line.txt

```

## ถ้า gate ไม่ผ่าน

แก้ **เนื้อหา** (episode/clip/`from`/ข้อความ/การ์ด) แล้วรัน gate นั้นใหม่ ห้ามแก้ gate/threshold/สคริปต์/ lock ห้ามลบ log ห้าม "resume" ด้วยการแก้สคริปต์ (สคริปต์ที่ยาวจะ resume ได้เองด้วย exit 75 + id เดิม) exit code ของ `finalize.py` = class ที่สูงสุดที่พบ (3 > 4 > 2 > 1) — exit 2 อาจบังการล้มด้านคุณภาพของ gate อื่น จึงต้องอ่านทุก gate ที่ล้มใน output/`.FAILED.json` ไม่ใช่แค่ตัวเลข:
- **0** ส่งมอบแล้ว (เขียนไฟล์ปลายทาง + receipt)
- **1** คุณภาพไม่ผ่าน → อ่านเหตุผลใน output/`.FAILED.json` (gate `word-timing`/`asr-recheck` ล้ม = timing ไม่ตรงเสียง/ไฟล์ถูกแก้: ห้ามแก้ไฟล์ timing; avatar/script เปลี่ยนจริงจึงรัน `word_timing.sh` ใหม่แล้วทำขั้น 2–11 ต่อ ไม่เช่นนั้นให้ขั้นล้ม; `word_timing.sh` exit 5 ในขั้น 2 = ขั้นล้มทันที) แก้เนื้อหา กลับไปขั้นที่เกี่ยวข้อง และรัน layout → render → mux → finalize ใหม่ถ้าอินพุตเปลี่ยน
- **2** ไฟล์บังคับของขั้น 11 หาย / report เก่า/หาย/อินพุตเปลี่ยนระหว่างรัน → รันขั้นที่ report นั้นมาจากใหม่ (7/8/9) แล้ว finalize ซ้ำ
- **3** ไฟล์ใน skill ถูกแก้/ไม่อยู่ใน `gates.lock.json` หรือ lock ไม่ล็อกไฟล์ engine ที่ `node "$SKILL/scripts/gate_integrity.mjs" remotion-composer --list-external` พิมพ์ → **หยุด** ห้ามแก้/สร้าง lock ใหม่ รายงานเป็นล้มเหลวพร้อมรายชื่อไฟล์
- **4** เครื่องมือ/gate ไม่มีหรือ crash/timeout (รวมเกินงบ 450 s ทั้งคำสั่ง — ถูกฆ่ากลางทางรันซ้ำได้ทันที; `--check` งบ 600 s; exit 4 ที่ต้นคำสั่งด้วย `environment: <ชื่อ>` = เช็กชุดเดียวกับ preflight **รวม `word-timing` (ASR venv/model/pin/ffmpeg) ที่รันทุกโหมดแม้ตอนส่งมอบ** ยกเว้น `music-library` ซึ่งเป็น preflight เท่านั้น ยังไม่ได้รันอะไร; toolchain ของ `raw_asr.json` ต่างจากเครื่องนี้ก็เป็น exit 4) → รายงานล้มเหลว (ลองซ้ำได้หนึ่งครั้งถ้าเป็น timeout) ห้ามข้าม gate ห้ามติดตั้ง/ซ่อม venv หรือ model cache (hint `setup_asr_venv.sh` = งานของคน) · ถ้า `word-timing` ล้มพร้อม hint `the OS was updated after this word timing was made — redo the word timing step and deliver again` ให้ทำตามนั้น: รันคำสั่ง `word_timing.sh` เดิมซ้ำ (มันถอดเสียงใหม่เองเพราะ job key รวม fingerprint ของ toolchain — OS/ffmpeg/mlx/venv เปลี่ยน = job ใหม่ ผลเก่าถูกลบโดยสคริปต์; toolchain เดิม = พิมพ์ "done" ทันที) แล้วทำขั้นที่ขึ้นกับมันซ้ำตั้งแต่ขั้น 2 เป็นต้นไป และส่งมอบใหม่ ห้ามแก้ marker/sha/ไฟล์ timing และห้ามลบหรือย้ายไฟล์เอง; อ่าน fingerprint ไม่ได้ = exit 4 หยุดและรายงาน
