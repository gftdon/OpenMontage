## Unattended policy (V4, มีผลเหนือข้อความด้านล่างเมื่อขัดกัน)

รันแบบไม่มีคนดู (`claude -p`) กฎนี้ถูกบังคับด้วยโค้ด ไม่ใช่คำแนะนำ:

- **Stock / AI footage ใช้ได้เฉพาะ clip ที่มี verdict ผ่าน (`verified`) ใน `artifacts/relevance.json`** ของ beat นั้น (จับคู่ด้วย `src` หรือเวลา `t`) ถ้าไม่มีงบจ่ายเงินที่อนุมัติ ก็ไม่มี verdict เลย → ใช้ footage ต้นฉบับ (`origin:"source"`) และการ์ดข้อความ (`media:"typo"`: `card` / `summary3` / `final4` / `vs`) ที่เนื้อหามาจาก script เท่านั้น ห้ามสร้างภาพ AI และห้ามเรียก API ที่เสียเงินทุกชนิด ห้ามหยิบผลค้นอันดับแรกของ stock มาใช้ "ไปก่อน"
- `verification_status` ของ relevance มี 3 ค่า (อ่านค่านี้ ไม่ใช่ `pass`):
  - `verified` = มี verdict ถูกต้องครบ coverage (score 1/2, AI ต้อง `readable_text:false`) → beat นั้นใช้ได้
  - `unverified` = ยังไม่มีหลักฐานพอ (ไม่มี verdict/ไม่มีงบ/ระบบใช้ไม่ได้) → **ใช้ stock/AI ไม่ได้** `lint_content.py` ให้ `stock-unverified` (error) ทุก beat ที่ใช้ `origin` stock/ai ที่ไม่มี verdict ผ่าน; `finalize.py` แค่บันทึกสถานะนี้ การบังคับอยู่ที่ `lint_content.py` ซึ่ง finalize รันสดทุกครั้ง
  - `failed` = มี verdict ปฏิเสธ (score 0 หรือ `readable_text:true`) หรือโครงสร้างผิด → `finalize.py` ออก exit 1
- Source footage ไม่ต้องมี relevance verdict แต่ต้องผ่าน "ดูแล้วตรงกับบรรทัดที่พูด": `artifacts/visual_evidence.json` + `lint_content.py` (`evidence-missing`, `evidence-weak`, `cue-mismatch`, `subject-not-in-window`) + `frame_checks.py cutaways` (watermark / ภาพว่าง / ใช้ shot ซ้ำ / `static-hold`)
  - evidence: ทุก `subject_terms` ต้องมีคำ ≥ 4 ตัวอักษรที่ไม่อยู่ใน stoplist (ตัวเลขล้วนไม่นับ) ที่พบใน OCR ของเฟรม beat นั้นหรือ transcript ต้นฉบับ ณ ช่วงที่แสดง (± 3 s) — ชื่อ chapter ไม่นับ; `seen` ≥ 15 ตัวอักษร; ไม่มีเสียงพูดและไม่มีข้อความบนจอ = `window-evidence-unavailable` (พิสูจน์ไม่ได้ → ใช้การ์ดจาก script)
  - `blank-frame` บน clip ต้นฉบับ = error เมื่อภาพที่มองเห็นเกือบว่างต่อเนื่อง ≥ 1 s (ข้อความบอกช่วงเวลาในไฟล์ clip: ขยับ `from` พ้นช่วงนั้น); 0.5–1 s = warning; สั้นกว่า 0.5 s ไม่รายงาน; stock/ai = error เสมอ · "เกือบว่าง" = พิกเซลในพื้นที่ที่มองเห็น (ย่อ 160×90) ที่ความสว่างต่างจากค่ากลางของเฟรมเกิน 40 มีน้อยกว่า 2 % · **ภาพซีด/contrast ต่ำที่ยังมีรายละเอียด (แบบแปลน, โมเดลสีขาว, หน้าเว็บ/เอกสารพื้นขาว) ไม่นับเป็นเฟรมว่าง** — ไม่มีเกณฑ์ค่าเฉลี่ย/ค่าเบี่ยงเบน (lead ตัดสิน 2026-11-12; มี test ยึดไว้ใน `test_frame_checks.py`)
  - การ์ด: `card-timing-far` (เลขที่ไม่ถูกพูดภายใน 30 s; `summary3`/`final4` ยกเว้น) · เศษส่วนในทุกรูป ("8 จาก 10", "8/10", big `8` + label `/10`) ต้องมีทั้งสองเลขใน script พูดติดกัน · `typo-filler` (ข้อความการ์ดเกิน 30 % ที่ script ไม่รองรับ) · การ์ดใบแรกของ `card` เริ่มที่ต้น beat (S14) และต้องยังอยู่บนจอตอนพูดเลขของมัน ใบ/ข้อ/stat ถัดไป ± 2 s

## A44 offline caption and media contract

- Use ONE audio-verified word-timing spine for captions, cue-linked semantic plans and visual timing. Keep vendor SRT as reference only (segmentation of lines, never timing); never blend timestamps or apply a guessed global offset. The legacy EP1 drift comment is not proof that a new episode is synchronized. Record input audio SHA, exact-phrase anchor checks and unresolved sync warnings. V4 default timing source = local alignment (`scripts/word_timing.sh`: offline forced alignment of the exact script onto Whisper word times, local cached models only, no downloads, no cloud); `timing_check.py` proves the result was measured from this audio. Timing files are never edited by hand.
- `source_context.py --word-timing ... --exact-script ...` keeps `reference_srt_cues` separate. Supplied `task/source/source.json` + `transcript.txt` wins even if untimed. Untimed source text is semantic context, never narration timing. Offline fallback records missing source/errors and never fetches or translates.
- Timing policy approved for this episode after two local phrase anchors within ±0.3s; evidence `projects/v261107-001-yt-news-v3-broll-test/qc/timing-local-asr/anchor-comparison.json` (independent main check). Individual word tails can differ >0.3s; do not claim word-end accuracy. Highlight uses latest lexical word START through next start, not raw `e`; page end uses next lexical start or explicit phrase/media bound. Original `s/e` are retained unchanged; `displayStart/displayEnd/displayBoundReason` are separate derived fields. Final episode bound 336.62s is the measured original avatar audio duration, not a fabricated word end. No ASR spelling substitution.
- `caption_join.mjs` exports `buildCaptionPages(tokens, exactScript, options)`. Script whitespace is authoritative, ASR token whitespace is not. Sequential exact character matching fails with offsets on mismatch. ICU words spanning ASR fragments merge with min/max original timing and `merged_from`; no invented subword timing. The exact lexical overrides `GPT-Image-2.6` and `บอกว่า` join only exact spans. Pause/width/punctuation coalescing improves pages but is NOT a guarantee of natural semantic Thai phrases. Render zero artificial gap, nowrap lexical chunks, actual script spaces only, unchanged Gold Glow/font/lane dimensions.
- Caption repair (3rd iteration): pagination width counts graphemes and duration compares unit starts (not pause-extended ends). `pause` is an observed start-gap heuristic, not a silence detector; without explicit phrase bounds, the page remains until the next start. Dependent closing marks attach to the preceding unit, equal starts share a display group, and overlapping overrides union whole ICU spans. `text/leadingWhitespace/spaceBefore` preserve exact data while `displayText/displaySpaceBefore` suppress only page-leading whitespace to avoid blank first lines. Long indivisible ICU words may exceed the width budget and require manual review, never a mid-word cut.
- Reproduce with `node scripts/caption_join.mjs --tokens <caption_pages.json> --script <script.txt> --options <caption-options.json> --out <caption-joined.json>` (V4 has no `--module` and no generated TS module; the engine reads the JSON). Input SHA (`inputSha256`) includes tokens/script/options and must equal `captionsInputSha256` in `episode.json`. Original per-ASR tokens remain in `sourceTokens`. If it fails, re-run the upstream step or fail the step; never edit the tokens. `caption-options.json` may contain ONLY `endTime` (= `voEndSec` within 0.01 s) and optional `lexicalOverrides` (list of strings); `finalize.py` re-runs `words_by_line.py`, `line_starts.py` and `caption_join.mjs` from `artifacts/word_timing/caption_pages.json` (and `srt_to_script.py --strict` for `script.txt`) and requires byte-identical outputs, so any hand edit of those files fails delivery.
- Caption algorithm start-6 (CF-A67): local forced alignment sometimes collapses the LAST word of a script line to zero length onto the start of the next line (real case V261111, tokens 719-722). That word's own display window would be empty, so it joins the display group of the word before it on the SAME line (`merged_from`/`sourceTokens` keep the original tokens; no timestamp is invented; the line break stays). A zero-length word that is alone on its line still fails closed (`simultaneous starts across newline`). `--options` must contain `endTime` (= `voEndSec`); `{}` fails with `explicit phrase/endTime bound required`. `--module` is rejected (exit 2).
- Source authority repair: SRT-only inputs always produce `timing_authority:'none'` and no narration cues. Plan validation consumes the WHOLE context and requires `timing_authority:'existing-word-spine'` plus `sync_verification:{status:'accepted',reference:...}`. Bare cue arrays/provisional sync cannot pass. Every strictly positive-overlap cue is required once in chronological order; zero edge overlap is excluded.
- Reconcile with `broll_plan.py --plan ... --context ... --beats <episode.json> --manifest ... --cuts ... --out ...` (all required; `--beats` is the V4 `episode.json`, never a `.tsx`). Plan interval/path/origin/from/source range and hash-derived identity must match the actual `beats` of `episode.json` and the cut records.
`--diagnostic-subset` permits four draft beats but always reports acceptance `pass:false, complete:false`; full acceptance requires all rendered cutaways. Candidate-only plans intentionally fail render reconciliation until Phase B selects real assets.
- Loop checking probes actual public MP4 duration and parses the declared duration table (V4: `brollDur` in `episode.json`); missing entries or mismatch greater than one frame fail, regardless of stale manifest/Pixabay duration. Loop availability uses the actual renderer table and `from`, not nominal download duration.
- `broll_plan.py` validates manually agent-authored query/rationale against exact overlapping cue IDs and spoken text. Validation proves linkage and source-priority rejection reasons, not semantic relevance. Source footage/UI first, AI only abstract concepts, stock last. Candidate plans are not accepted assets.
