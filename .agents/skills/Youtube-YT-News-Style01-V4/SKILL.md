# Youtube YT News Style01 V4

ผลลัพธ์ = วิดีโอข่าว 1920×1080 @25fps ที่ render จากข้อมูลล้วน (`episode.json` + captions JSON) ด้วย engine ตัวเดียวที่ล็อกไว้ แล้วส่งมอบผ่าน `finalize.py` เท่านั้น
**gate เขียวไม่ได้แปลว่าวิดีโอดี** — gate ตรวจเรขาคณิต/ข้อความ/เสียง ไม่ได้ตรวจว่าภาพตรงกับคำพูด คุณต้อง "เปิดดู" ภาพจริงด้วยเครื่องมือ Read ในขั้น 1, 5 และ 10
สัญญาข้อมูล: `references/v4-contract.md` · แหล่ง YouTube: `references/yt-source.md` · geometry: `references/format-spec.md` · ซ้ำของ B-roll: `references/broll-freshness.md`

## กติกาเหล็ก

1. ส่งมอบได้ทางเดียว (= finalize; ปลายทางมีได้มากกว่าหนึ่ง ดูขั้น 0/11): `$PY "$SKILL/scripts/finalize.py" --project projects/<slug> --deliver <path>` prompt ที่สั่ง "ย้าย/copy mp4 ไป <path>" = สั่งให้รัน finalize ด้วย path นั้น (ปลายทางหลัก = ไฟล์ผลลัพธ์ที่ task ระบุให้เขียน; ถ้ามี `request.json` คือ `outputs[0]`) ถ้า finalize ไม่ exit 0 ขั้นนี้ **ล้มเหลว**: รายงานเหตุผลจาก output และ `<path>.FAILED.json` (เขียนเฉพาะการรันจริง; `--check` ไม่เขียนไฟล์นี้) ห้าม cp/mv/rename/เขียนไฟล์ที่ปลายทางด้วยวิธีอื่น
2. ห้ามสร้าง/แก้ `.tsx`, engine, Root, `remotion-composer/src/**`, ไฟล์ใดใต้ `.claude/skills/**` หรือ `.agents/skills/**`, `gates.lock.json`; ห้าม commit ในโฟลเดอร์เหล่านี้; ห้าม copy ไฟล์จากโปรเจกต์ตอนอื่น; ห้ามลด threshold
3. ห้ามแก้ไฟล์ script/timing/captions ด้วยมือ (`script.txt`, `caption_pages.json`, `words_by_line.txt`, `line_starts.json`, `caption-joined.json`, `caption-options.json`) — finalize สร้างซ้ำจากต้นน้ำแล้วเทียบทุก byte (gate `script`/`derived`): แก้มือ = ส่งมอบไม่ผ่าน; `caption-options.json` มีได้เฉพาะ `endTime` (= `voEndSec` ± 0.01 s) กับ `lexicalOverrides` ถ้า `caption_join` / `lint_captions` / `timing_check` ล้ม ให้รันขั้นต้นน้ำซ้ำหรือให้ขั้นล้ม
4. ต้องเปิดภาพดูจริง (Read) ก่อนเขียนว่า "ภาพตรงคำพูด": contact sheet ต้นฉบับ, เฟรม cutaway, เฟรมวิดีโอสุดท้าย ไม่เคยเปิด = ห้ามเขียนข้อความนั้น; `srcCrop` ใส่ได้เฉพาะเมื่อซูมโดยตั้งใจและเปิดเฟรมแล้วเห็นว่าไม่ตัดเนื้อหา (ค่าเริ่ม = ไม่ใส่ ไม่มี gate ตรวจให้)
5. Stock/AI footage ใช้ได้เฉพาะ clip ที่มี verdict `verified` ใน `artifacts/relevance.json`; ไม่มีงบจ่ายเงินที่อนุมัติ = ไม่มี verdict = ใช้ footage ต้นฉบับ + การ์ดข้อความ (`typo`) ที่เนื้อหามาจาก script ห้ามสร้างภาพ AI ห้ามเรียก API ที่เสียเงิน (`fetch_broll.py` ใช้ได้เฉพาะ `--music` ขั้น 9; สัญญา paid/relevance: `references/v4-contract.md`)
6. ตัวเลข/ลำดับ/ชื่อบนจอต้องมีใน script หรือต้นฉบับ ห้ามเขียนป้ายที่เพิ่มข้อเท็จจริงเอง เวลาของ stat/card/item/lower ทุกตัว (`at`) มาจาก `cue_times.py` (ความคลาดเคลื่อน ±2 s; ป้ายของทั้ง beat เช่น headline/sub ต้องยังอยู่บนจอตอนพูดตัวเลขนั้น)
7. ลำดับตายตัว: layout gate เสร็จและผ่าน → render จริง → mux → finalize ห้ามสลับ/ข้าม/render ก่อน gate จบ; หลัง layout ผ่านห้ามแก้ episode/captions/media (แก้ = กลับไปขั้น 6 แล้วรัน layout ใหม่)
8. ทุกคำสั่งต้องจบ < 8 นาทีหรือ resumable: exit 75 = เรียกคำสั่งเดิมซ้ำ (ตามขั้น 7/8, `word_timing.sh`); ห้ามห่อด้วย `sleep` ยาว
9. สัดส่วน: presenter-only (`mode:"full"`) รวม ≤ 25 % ของ VO (ไม่นับ cold open ≤ 10 s กับ beat สุดท้าย) และต่อเนื่อง ≤ 12 s ที่เหลือเติมด้วย source/การ์ดจาก script; punch เฉพาะ beat `full` ไม่ใช่ `pip` และไม่ที่/หลัง `ctaT`; CTA ≤ 40 ตัวอักษรที่ไม่ใช่ช่องว่าง (`lint_content` `cta-length`)
10. ห้าม dark wash คลุมภาพ footage (ภาพต้นทาง / stock) ทั้งภาพ · อนุญาตพื้นทึบหรือ wash เฉพาะพื้นของ beat การ์ดข้อความ (`media:"typo"`) ซึ่งไม่มี footage อยู่ข้างใต้ · ข้อความที่วางบน footage ใช้พื้นรองเฉพาะจุดใต้ข้อความเท่านั้น

## ขั้นตอน (ทำตามลำดับ ห้ามข้าม)

ให้ `SKILL=.claude/skills/Youtube-YT-News-Style01-V4`, `P=projects/<slug>`, `PY=python3` (python ระบบไม่มี pythainlp: ถ้า preflight ขั้น 0 ล้มเพราะ module `numpy`/`PIL`/`pythainlp` ให้สลับ `PY=$PWD/.venv/bin/python` แล้วรันใหม่ — สลับได้แค่นี้) แล้วใช้ `$PY` กับทุก `.py`; รันทุกคำสั่งจาก root ของ worktree ตอน; `<assetDir>` = ชื่อโฟลเดอร์ใหม่ใต้ `remotion-composer/public/`

**0. Setup** — **คำสั่งแรกของงาน ต้อง exit 0:** `$PY "$SKILL/scripts/finalize.py" --preflight` (ตรวจ node/ffmpeg/ffprobe/git/swift, `numpy`/`PIL`/`pythainlp`, `remotion-composer/node_modules` (remotion, @remotion/bundler, @remotion/renderer), ฟอนต์ `Kanit-Bold.ttf` + `Kanit-ExtraBold.ttf`, gate lock, whisper ในเครื่องของ `word_timing.sh`, คลังเพลงที่อนุมัติ `music-library` (ไม่มีเพลงที่ใช้ได้ = FAIL exit 4); พิมพ์ `PREFLIGHT ok|FAIL <ชื่อ>: …` แล้วสรุป `PREFLIGHT PASS` หรือ `PREFLIGHT FAIL (exit N)`) ล้ม = ขั้นล้มทันทีโดยใช้บรรทัด `PREFLIGHT FAIL` เป็นเหตุผล (exit 4 = เครื่องมือ/แพ็กเกจ/ฟอนต์/whisper/คลังเพลง `music-library` ขาด, exit 3 = gate lock) ห้ามเริ่มสำรวจต้นฉบับ ห้ามติดตั้ง/ดาวน์โหลด/สร้างอะไร (ฟอนต์ venv แพ็กเกจ model) ห้ามลอง Python ตัวอื่น; `remotion-composer/public/`, `.venv` และ `music_library/` (หรือ path absolute ใน env `MUSIC_LIBRARY_DIR`) ถูก git-ignore จึงมีเฉพาะใน checkout ที่เริ่มงาน
จากนั้น slug และ `<assetDir>` ใหม่ (ห้ามใช้ซ้ำของตอนอื่น) copy ไม่ symlink:
`mkdir -p $P/{artifacts,assets/ytsource,assets/audio,qc/arcs,qc/final-frames,renders} remotion-composer/public/<assetDir>/broll` · script ต้นฉบับ → `$P/artifacts/source_script.txt` (กับ SRT ด้านล่างเป็นไฟล์บังคับ: finalize สร้าง `script.txt` ซ้ำจากสองไฟล์นี้) · avatar mp4 → `remotion-composer/public/<assetDir>/avatar_source.mp4` · SRT → `$P/assets/avatar.srt` · จดปลายทางส่งมอบ: **ปลายทางหลัก** = ไฟล์ผลลัพธ์ที่ task ระบุให้เขียน ("ไฟล์ผลลัพธ์ที่ต้องเขียน"; ถ้า task ให้ `request.json` ตอนรัน คือ `outputs[0]` ของไฟล์นั้น) ลงบรรทัดเดียวใน `$P/artifacts/deliver_path.txt` = `--deliver` ของขั้น 11; ถ้า prompt ระบุที่อื่นให้ส่ง mp4 ไปด้วย (เช่นประโยคเก่า "ย้ายไฟล์ .mp4 ไปยัง Folder … ตั้งชื่อเป็น …") นั่นคือปลายทางที่สอง ให้จด path ลง `$P/artifacts/deliver_extra.txt` บรรทัดละหนึ่ง path — ต้องเป็น path ที่เขียนไว้ตรงตัวใน prompt (เติมได้เฉพาะ placeholder ที่ prompt นิยามเอง เช่น `<Video Code>`) ห้ามคิดปลายทางเอง.
ตรวจ: preflight exit 0 และมี `$P/artifacts/{source_script.txt,deliver_path.txt}`, `$P/assets/avatar.srt`, avatar ใน `remotion-composer/public/<assetDir>/`

**1. สำรวจต้นฉบับ** — `bash "$SKILL/scripts/yt_survey.sh" "<URL>" $P/assets/ytsource` ได้ `source.mp4`, `chapters.txt` (เขียนเสมอ; วิดีโอไม่มี chapter = มีแค่บรรทัด `# title`/`# duration`; ถ้าไม่ได้รันสคริปต์นี้เต็มชุด เช่น `--frames-only` ไฟล์อาจไม่มี), `survey/dense/sheet_*.jpg` + `index.json`, `transcript_timed.json` (ไม่มี → `source_timed.py from-audio` เป็นช่วง ≤ 300 s แล้ว `merge`) แล้วสร้าง `assets/ytsource/transcript.txt` จาก `transcript_timed.json` ทุกครั้ง — คำสั่งใน `references/yt-source.md` §1
**ต้องเปิดทุก** `survey/dense/sheet_*.jpg` ด้วย Read แล้วเขียน `$P/artifacts/survey_notes.md` หนึ่งบรรทัดต่อ chapter: เวลา | สิ่งที่เห็นจริงบนจอ | ใช้กับบรรทัด script ไหนได้
ตรวจ: จำนวน sheet ที่เปิด = จำนวนไฟล์ใน `index.json`; ทุก chapter มีบรรทัดใน notes

**2. Script + word timing + captions** (ข้อความมาจาก script ต้นฉบับ; SRT ใช้แบ่งบรรทัดเท่านั้น ไม่ใช้เวลา)
```
$PY "$SKILL/scripts/srt_to_script.py" --srt $P/assets/avatar.srt --script $P/artifacts/source_script.txt --strict --out $P/artifacts/script.txt   # exit 1 = เสียงพากย์ต่างจาก script → ขั้นล้ม
bash "$SKILL/scripts/word_timing.sh" remotion-composer/public/<assetDir>/avatar_source.mp4 $P/artifacts/script.txt $P/artifacts/word_timing   # exit 75 = เรียกซ้ำด้วยอาร์กิวเมนต์เดิมไปเรื่อย ๆ (คลิป 11 นาทีวัดจริง 3 รอบ ≈ 425 s, 421 s, 135 s; คาดไว้ 2–4 รอบ รอบละ ≤ ~7 นาที); exit อื่นที่ไม่ใช่ 0/75 = ขั้นล้ม (4 = ไม่มี tool/model ในเครื่อง ไม่ดาวน์โหลดให้)
$PY "$SKILL/scripts/words_by_line.py" $P/artifacts/word_timing/caption_pages.json $P/artifacts/script.txt > $P/artifacts/words_by_line.txt
$PY "$SKILL/scripts/line_starts.py" --pages $P/artifacts/word_timing/caption_pages.json --script $P/artifacts/script.txt --out $P/artifacts/line_starts.json
$PY "$SKILL/scripts/timing_check.py" --audio remotion-composer/public/<assetDir>/avatar_source.mp4 --words $P/artifacts/words_by_line.txt --srt $P/assets/avatar.srt --line-starts $P/artifacts/line_starts.json --report $P/qc/timing-check.json
VO_END=$(ffprobe -v error -show_entries format=duration -of csv=p=0 remotion-composer/public/<assetDir>/avatar_source.mp4)   # ความยาวเสียงพากย์ = voEndSec ในขั้น 4
$PY -c "import json,sys;json.dump({'endTime':round(float(sys.argv[1]),3)},open(sys.argv[2],'w'))" "$VO_END" $P/artifacts/caption-options.json   # เพิ่มได้เฉพาะ "lexicalOverrides":[ชื่อเฉพาะที่สะกดตรงกับ script] ห้ามใส่ค่าเวลาอื่น (finalize ตรวจ endTime กับ voEndSec ± 0.01 s)
node "$SKILL/scripts/caption_join.mjs" --tokens $P/artifacts/word_timing/caption_pages.json --script $P/artifacts/script.txt --options $P/artifacts/caption-options.json --out $P/artifacts/caption-joined.json
$PY "$SKILL/scripts/lint_captions.py" --script $P/artifacts/script.txt --pages $P/artifacts/caption-joined.json --source-script $P/artifacts/source_script.txt --report $P/qc/captions-lint.json
```
ตรวจ: ทุกคำสั่งออก 0 (`timing_check` = 0 พิสูจน์ว่า timing วัดจากเสียงนี้ ไม่ใช่พิมพ์มือ; `lint_captions` = 0 คือไม่มีคำไทยถูกตัดกลางคำ) ล้มข้อใด → รันขั้นต้นน้ำใหม่หรือให้ขั้นล้ม ห้ามแก้ตัวเลขเวลา

**3. วางแผนภาพทีละบรรทัด script** — source ก่อน: จาก `survey_notes.md` + transcript หาว่า "ต้นฉบับแสดงสิ่งที่บรรทัดนี้พูดถึงตรงไหนของจอ" แล้วตัดให้สิ่งนั้นอยู่บนจอทั้ง beat
`bash "$SKILL/scripts/cut_clips.sh" $P/assets/ytsource/source.mp4 $P/assets/ytsource/clips yt_<topic>:<start>:<end> ...` → `cp $P/assets/ytsource/clips/_cuts.json $P/artifacts/_cuts.json` → copy `yt_*.mp4` ไป `remotion-composer/public/<assetDir>/broll/`
`from` = วินาทีเริ่มเล่นภายในไฟล์ที่ตัดแล้ว (ไม่ใช่เวลาใน YouTube): ตัดหรือตั้ง `from` ให้ภาพที่ป้ายอ้างถึงอยู่ตั้งแต่ต้น beat; ไม่มี stock ที่ verified → ใช้การ์ดข้อความ (`card`/`summary3`/`final4`/`vs`) จาก script รายละเอียด: `references/yt-source.md` §2–4
ตรวจ: ทุกบรรทัดที่ไม่ใช่ presenter มี clip หรือการ์ด; ไม่มี clip ที่ตัดจากชื่อ chapter โดยไม่เคยเห็นภาพ

**4. เขียน `$P/artifacts/episode.json`** ตามตารางใน `references/v4-contract.md` (ค่าทุกตัวเป็นของตอนนี้; ห้ามเหลือข้อความ/ชื่อไฟล์ของตัวอย่าง) แล้วเติมด้วยคำสั่ง ไม่ใช่เดา:
- `brollDur[src]` = `ffprobe -v error -show_entries format=duration -of csv=p=0 remotion-composer/public/<assetDir>/broll/<src>.mp4`
- `captionsInputSha256` = ค่า `inputSha256` ใน `caption-joined.json`; `voEndSec` = `endTime` ที่ใช้ในขั้น 2 (ความยาวเสียง avatar; schema S19 ตรวจกับ captions) · `totalDurationSec` = `voEndSec` + 3..5 · `ctaT` = เวลาที่พูดคำถามปิดท้าย (`cue_times.py`) ต้อง < `voEndSec` และ ≥ `t` ของ beat สุดท้าย ซึ่งต้องเป็น `mode:"full"` (S20)
- `from` + ความยาว beat: คลิปต้องยาวพอสำหรับช่วงที่โชว์ **บวกช่วงที่ภาพเก่ายังค้างตอนเปลี่ยนฉาก (สูงสุด 0.92 s = stage↔wide)** — `from + (ความยาว beat) + 0.92 + ~0.12 ≤ brollDur[src]` (engine หัก 2 เฟรม + ปัดเศษเฟรม) คลิปต้นฉบับห้ามวน/ค้างเฟรมสุดท้าย (S09 = error; ข้อความ error บอกจำนวนวินาทีที่ต้องลด `from`); stock ที่สั้นไป = warning (วนกลับต้นคลิป) คลิปเดียวใช้หลาย beat ได้เฉพาะคลิปต้นฉบับและช่วงที่เล่นต้องไม่ซ้อนกัน (S10)
- `avatarFile` = `avatar_source.mp4` (ไฟล์เดียวกับที่ใช้วัด timing ขั้น 2 — finalize รัน `timing_check` บน `remotion-composer/public/<assetDir>/<avatarFile>`) · `avatarFaceBox`: `ffmpeg -i <avatar> -vf "fps=12/<durSec>,scale=960:-1,tile=4x3" -frames:v 1 $P/qc/face_tile.jpg` เปิดดู → กรอบรวมศีรษะ (ยอดผม–คาง, หูซ้าย–ขวา) ใน 12 ช่อง → หารด้วยขนาดช่อง (960×540) → pad ≈ 0.06 รอบด้าน ปัดออกถึง 0.01, clamp 0..1 (ขั้น 7 ตรวจจากพิกเซลว่าไม่มีข้อความ/พื้นรองทับหน้า: `face-text`/`face-backing`)

- ทุก `at` (stats/cards/items/lower/punch): `$PY "$SKILL/scripts/cue_times.py" --words $P/artifacts/words_by_line.txt --script $P/artifacts/script.txt --find "<ตัวเลขหรือวลีที่พูด>" [--near T]` ใช้ `start` ที่ได้

หลัง finalize exit 0 เท่านั้น ลบ bundle ชั่วคราว (ราว 570 MB ต่อ run): `rm -rf $P/qc/layout/runs/*/bundle $P/renders/visual.render/*/bundle` — ห้ามลบ `report.json`, `run-manifest`, receipt หรือไฟล์ใน `renders/` อื่น และห้ามลบก่อน finalize ผ่าน
**12. ผลของขั้น**: สำเร็จก็ต่อเมื่อ finalize exit 0 ที่ปลายทางหลัก — ระบุ path ปลายทางและ `<deliver>.receipt.json` ของทุกปลายทาง และถ้าปลายทางเพิ่มล้มต้องเขียนว่าล้มอย่างชัดเจน (ผลของขั้นยึดปลายทางหลักตาม output ที่ task กำหนด); นอกนั้น = ล้มเหลว พร้อมเหตุผลของ **ทุก** gate ที่ล้มจาก output และ `<deliver>.FAILED.json` (ไม่มีไฟล์ที่ปลายทางที่ finalize ไม่ได้รับรอง)

## ถ้า gate ไม่ผ่าน

แก้ **เนื้อหา** (episode/clip/`from`/ข้อความ/การ์ด) แล้วรัน gate นั้นใหม่ ห้ามแก้ gate/threshold/สคริปต์/ lock ห้ามลบ log ห้าม "resume" ด้วยการแก้สคริปต์ (สคริปต์ที่ยาวจะ resume ได้เองด้วย exit 75 + id เดิม) exit code ของ `finalize.py` = class ที่สูงสุดที่พบ (3 > 4 > 2 > 1) — exit 2 อาจบังการล้มด้านคุณภาพของ gate อื่น จึงต้องอ่านทุก gate ที่ล้มใน output/`.FAILED.json` ไม่ใช่แค่ตัวเลข:
- **0** ส่งมอบแล้ว (เขียนไฟล์ปลายทาง + receipt)
- **1** คุณภาพไม่ผ่าน → อ่านเหตุผลใน output/`.FAILED.json` แก้เนื้อหา กลับไปขั้นที่เกี่ยวข้อง และรัน layout → render → mux → finalize ใหม่ถ้าอินพุตเปลี่ยน
- **2** ไฟล์บังคับของขั้น 11 หาย / report เก่า/หาย/อินพุตเปลี่ยนระหว่างรัน → รันขั้นที่ report นั้นมาจากใหม่ (7/8/9) แล้ว finalize ซ้ำ
- **3** ไฟล์ใน skill ถูกแก้/ไม่อยู่ใน `gates.lock.json` หรือ lock ไม่ล็อกไฟล์ engine ที่ `node "$SKILL/scripts/gate_integrity.mjs" remotion-composer --list-external` พิมพ์ → **หยุด** ห้ามแก้/สร้าง lock ใหม่ รายงานเป็นล้มเหลวพร้อมรายชื่อไฟล์
- **4** เครื่องมือ/gate ไม่มีหรือ crash/timeout (รวมเกินงบ 450 s ทั้งคำสั่ง — ถูกฆ่ากลางทางรันซ้ำได้ทันที; exit 4 ที่ต้นคำสั่งด้วย `environment: <ชื่อ>` = เช็กชุดเดียวกับ preflight ยกเว้น `word-timing` กับ `music-library` ซึ่งเป็น preflight เท่านั้น ล้มตอนส่งมอบ ยังไม่ได้รันอะไร) → รายงานล้มเหลว (ลองซ้ำได้หนึ่งครั้งถ้าเป็น timeout) ห้ามข้าม gate

## ข้ออ้างที่ห้ามใช้

| ข้ออ้าง | ความจริง |
|---|---|
| "gate ของ engine ผ่านหมดแล้ว" | gate เขียวไม่ได้แปลว่าภาพตรงคำพูด ต้องเปิดเฟรมดู (ขั้น 5 และ 10) |
| "ไม่ได้เปิดภาพ แต่ชื่อ chapter/ชื่อ clip บอกว่าตรง" | ป้ายที่เขียนจากชื่อไม่ใช่หลักฐาน ต้องเห็นภาพ ณ เวลาที่ใช้ |
| "`caption_join` ล้ม แก้เวลา 12 token เองก็พอ" | timing ที่แก้มือ = timing ปลอม ให้รัน `word_timing.sh` ใหม่หรือให้ขั้นล้ม |
| "layout gate ช้า ขอแก้สคริปต์ให้ resume ได้" | gate resume เองด้วย exit 75 + `--run-id` เดิม ห้ามแก้ไฟล์ใน skill |
| "ยังไม่ได้รัน layout เสร็จ แต่ render ไปก่อนประหยัดเวลา" | render ปฏิเสธ (exit 3) และ render ก่อนรู้ผล layout คือหลบ gate |
| "ไม่มี stock ที่ผ่าน ใช้ผลค้นอันดับแรกไปก่อน" | ไม่มี verdict = ห้ามใช้ ใช้ footage ต้นฉบับหรือการ์ดจาก script |
| "พิมพ์เวลาการ์ดเองเร็วกว่า / ตัวเลขนี้น่าจะถูก" | ใช้ `cue_times.py`; ตัวเลขที่ไม่มีใน script/ต้นฉบับห้ามขึ้นจอ ("รอบที่ 1", "8/10") |
| "copy ตอนเก่ามาแก้เร็วกว่า" | ห้าม copy composition/engine/ข้อมูลตอนอื่น เริ่มจากตาราง field ใน contract |
| "finalize fail แต่ไฟล์ดูดีแล้ว cp ไปปลายทางเองได้" | finalize ไม่ exit 0 = ไม่มีงานส่งมอบ ห้ามมีไฟล์ที่ปลายทาง |
| "ดึงเพลงไม่ได้ เลย copy bed จากงานก่อน/จากคลังเอง" | ห้าม ทางเดียวคือคำสั่ง fetch ขั้น 9 (มันหยิบจากคลังที่อนุมัติให้เอง); exit 4 = ขั้นล้ม ห้าม mux ไม่มีเพลง ห้ามลองดึงเพลงออนไลน์/หาเพลงอื่นเอง |

| "presenter พูดเต็มจอ 40 % ก็ไม่เป็นไร" | ≤ 25 % และ ≤ 12 s ต่อช่วง ที่เหลือเติม source/การ์ด |
